## Part C: static timing analysis

`sta/sta.tcl` uses the SKY130 HD typical-corner Liberty library and the assignment's 1.0 ns input and output delays. The clock period defaults to 10 ns and can be overridden with the `T` environment variable.

```bash
# Baseline timing run (T = 10 ns)
sta -no_splash -exit sta/sta.tcl 2>&1 | tee /tmp/sta_10ns.log
# Save the baseline detailed path report before the next command overwrites it
cp sta/mult_array_timing.rpt /tmp/mult_array_timing_10ns.rpt

# Tmin estimate: 10 - 7.396 = 2.604 ns; round UP to 2.61 ns
T=2.61 sta -no_splash -exit sta/sta.tcl 2>&1 | tee /tmp/sta_2p61ns.log
# Check actual worst slack and critical path from the measured report
cat /tmp/sta_2p61ns.log
grep -E 'Startpoint:|Endpoint:|slack \(' sta/mult_array_timing.rpt
```

The measured 10 ns worst setup slack is 7.396 ns, so the arithmetic minimum-period estimate is `Tmin = 10 - 7.396 = 2.604 ns`. Rounded **up** to the next 0.01 ns, the Part C target is 2.61 ns. Using the assignment formula and unrounded estimate, Fmax = 1000/2.604 ≈ 384.0 MHz. The rounded 2.61 ns verification period corresponds to 383.1 MHz and has measured critical-path setup slack of +0.006 ns.

**Measured Tmin check:** The saved `sta/mult_array_timing.rpt` was generated at **2.61 ns**. It records critical-path setup slack of **+0.006 ns (MET)** and reset-recovery slack of **+1.838 ns**.

That is comparable to the rough architectural estimate of about `2N = 8` full-adder delays for a 4-bit array, but synthesis remapped the RTL into standard-cell logic, so these are not eight literal full-adder instances.

Note on max-slew: the flow reports 4 maximum-slew violations, all in the max_ss_100C_1v60 corner (100 C, 1.60 V, slow transistors, worst-case RC). They are an additional electrical sign-off warning from the library's max_transition limit, not one of the assignment's pass criteria (DRC = 0, LVS = 0, setup slack >= 0). The typical corner has 0 slew, 0 cap and 0 fanout violations. We tried SYNTH_STRATEGY variants, SYNTH_SIZING, MFS3 and post-global-route design repair (see Table 5); because they changed timing or area without a clean result and relaxing limits only hides the warning, the submitted run keeps the plain flow.
